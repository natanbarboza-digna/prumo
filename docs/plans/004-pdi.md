# 004 — Categorias de ação e ciclos de PDI

Status: **aprovado** (16/11/2026)
Branch: `feat/pdi`

## Objetivo

Registrar os ciclos de PDI trazidos da empresa: o ciclo, as áreas de desenvolvimento, as ações de cada área, os check-ins com o gestor e a avaliação final. As ações usam um cadastro de **categorias** gerenciado pelo usuário. O campo `allowsRoutine` da categoria já é gravado agora, mas só passa a ter efeito na etapa 5 (criar rotina a partir de uma ação).

## Escopo

### Categorias de ação (`src/modules/categories/`)

- **Cadastro:** listar, criar, editar, arquivar e desarquivar.
- **Exclusão:** só é possível para categoria sem nenhuma ação. Categoria em uso lança `CategoryInUseError`, e a tela oferece arquivar no lugar. O banco também garante a regra (`onDelete: Restrict`).
- **Nome único** sem diferenciar maiúsculas ("prática" = "Prática"): `@unique` no banco e checagem `mode: "insensitive"` no service, com o erro no campo `name`.
- **Seed** (`npx prisma db seed`): "Prática" (`allowsRoutine = true`), "Curso", "Leitura" e "Mentoria" (`allowsRoutine = false`). É idempotente (upsert pelo nome) e não altera uma categoria que o usuário já editou. A lista fica em `src/modules/categories/defaults.ts`, usada pelo seed e pelos testes.
- Nenhum comportamento depende do nome da categoria.

### Ciclos de PDI (`src/modules/pdi/`)

- **Ciclo**
  - CRUD com `title`, `startDate` e `endDate` (obrigatórias, fim ≥ início), `managerName`, `careerObjective`, `selfAssessment`, `managerFeedback` e `finalRating`.
  - **Status:** `PLANNED` e `ACTIVE` são escolhidos no formulário. `CLOSED` só pelo botão **"Encerrar ciclo"**, com confirmação.
  - **Só um ciclo `ACTIVE` por vez** (pergunta 2). Ativar um segundo lança `ActiveCycleExistsError`, com a mensagem no campo `status`.
  - **Ciclo `CLOSED` é somente leitura.** O service recusa (`CycleClosedError`) qualquer mudança no ciclo, nas áreas, nas ações e nos check-ins dele, e também a exclusão. A única operação permitida é **"Reabrir ciclo"** (volta para `ACTIVE`, pergunta 3). Na tela, os botões de edição somem e aparece o aviso "Ciclo encerrado: somente leitura".
  - Excluir um ciclo exclui as áreas, as ações e os check-ins dele (com confirmação que avisa isso).
- **Área:** `name`, `description` e `expectedOutcome`; criar, editar e excluir (exclui as ações). Ordem de criação.
- **Ação**
  - Campos: `area`, `category`, `title`, `description`, `expectedResult`, `dueDate`, `status` (`NOT_STARTED`, `IN_PROGRESS`, `DONE`, `CANCELLED`), `evidence`, `managerComment` e `goalId` (opcional).
  - **Categoria arquivada** não pode ser escolhida para uma ação nova, nem para uma ação que troca de categoria (`CategoryArchivedError`, erro no campo). Uma ação que já usa uma categoria depois arquivada pode ser editada mantendo a categoria; no select, ela aparece como "Nome (arquivada)".
  - A área precisa ser do mesmo ciclo. Mover a ação para outra área do ciclo é permitido.
  - `goalId` inexistente lança `GoalNotFoundError`.
  - **Atrasada:** prazo vencido e status `NOT_STARTED` ou `IN_PROGRESS`.
  - Ordem dentro da área: prazo (sem prazo por último), depois criação.
- **Check-in:** `date` (obrigatória), `summary` (obrigatório), `nextSteps` e `managerNotes`; criar, editar e excluir. Lista do mais recente para o mais antigo.
- **Progresso do ciclo:** "X de Y ações concluídas". Ações canceladas ficam fora da conta.

### Objetivos

- O detalhe do objetivo ganha a seção **"Ações de PDI"**: as ações vinculadas, com ciclo, área, status e prazo.
- **Progresso agregado** (pergunta 5): `getGoalProgress` passa a somar etapas de trilha e ações de PDI (sem as canceladas). A barra de progresso sobe para o topo da página, com o texto "3 de 5 itens concluídos" e o detalhamento "2 de 3 etapas · 1 de 2 ações de PDI". Rotinas continuam fora, com adesão própria.
- O aviso ao excluir um objetivo cita trilhas, rotinas **e ações de PDI**.

## Mudanças no modelo de dados

```prisma
enum PdiCycleStatus {
  PLANNED
  ACTIVE
  CLOSED

  @@map("pdi_cycle_status")
}

enum PdiActionStatus {
  NOT_STARTED
  IN_PROGRESS
  DONE
  CANCELLED

  @@map("pdi_action_status")
}

model ActionCategory {
  id            String      @id @default(uuid(7)) @db.Uuid
  name          String      @unique @db.VarChar(60)
  allowsRoutine Boolean     @default(false) @map("allows_routine")
  archived      Boolean     @default(false)
  actions       PdiAction[]
  createdAt     DateTime    @default(now()) @map("created_at")
  updatedAt     DateTime    @updatedAt @map("updated_at")

  @@map("action_categories")
}

model PdiCycle {
  id              String         @id @default(uuid(7)) @db.Uuid
  title           String         @db.VarChar(120)
  startDate       DateTime       @map("start_date") @db.Date
  endDate         DateTime       @map("end_date") @db.Date
  status          PdiCycleStatus @default(PLANNED)
  managerName     String?        @map("manager_name") @db.VarChar(120)
  careerObjective String?        @map("career_objective")
  selfAssessment  String?        @map("self_assessment")
  managerFeedback String?        @map("manager_feedback")
  finalRating     String?        @map("final_rating") @db.VarChar(60)
  areas           PdiArea[]
  checkIns        PdiCheckIn[]
  createdAt       DateTime       @default(now()) @map("created_at")
  updatedAt       DateTime       @updatedAt @map("updated_at")

  @@index([status])
  @@map("pdi_cycles")
}

model PdiArea {
  id              String      @id @default(uuid(7)) @db.Uuid
  cycleId         String      @map("cycle_id") @db.Uuid
  cycle           PdiCycle    @relation(fields: [cycleId], references: [id], onDelete: Cascade)
  name            String      @db.VarChar(120)
  description     String?
  expectedOutcome String?     @map("expected_outcome")
  actions         PdiAction[]
  createdAt       DateTime    @default(now()) @map("created_at")
  updatedAt       DateTime    @updatedAt @map("updated_at")

  @@index([cycleId])
  @@map("pdi_areas")
}

model PdiAction {
  id             String          @id @default(uuid(7)) @db.Uuid
  areaId         String          @map("area_id") @db.Uuid
  area           PdiArea         @relation(fields: [areaId], references: [id], onDelete: Cascade)
  categoryId     String          @map("category_id") @db.Uuid
  category       ActionCategory  @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  title          String          @db.VarChar(160)
  description    String?
  expectedResult String?         @map("expected_result")
  dueDate        DateTime?       @map("due_date") @db.Date
  status         PdiActionStatus @default(NOT_STARTED)
  evidence       String?
  managerComment String?         @map("manager_comment")
  goalId         String?         @map("goal_id") @db.Uuid
  goal           Goal?           @relation(fields: [goalId], references: [id], onDelete: SetNull)
  createdAt      DateTime        @default(now()) @map("created_at")
  updatedAt      DateTime        @updatedAt @map("updated_at")

  @@index([areaId])
  @@index([categoryId])
  @@index([goalId])
  @@map("pdi_actions")
}

model PdiCheckIn {
  id           String   @id @default(uuid(7)) @db.Uuid
  cycleId      String   @map("cycle_id") @db.Uuid
  cycle        PdiCycle @relation(fields: [cycleId], references: [id], onDelete: Cascade)
  date         DateTime @db.Date
  summary      String
  nextSteps    String?  @map("next_steps")
  managerNotes String?  @map("manager_notes")
  createdAt    DateTime @default(now()) @map("created_at")
  updatedAt    DateTime @updatedAt @map("updated_at")

  @@index([cycleId, date])
  @@map("pdi_check_ins")
}

// Goal ganha a relação inversa:
//   pdiActions PdiAction[]
```

- **`onDelete`:** excluir ciclo ou área leva junto o que está dentro (`Cascade`); excluir objetivo só desfaz o vínculo (`SetNull`); categoria em uso não pode ser excluída (`Restrict`, além da checagem no service, que dá a mensagem amigável).
- **"Só um ciclo ativo"** fica no service, não no banco. Um índice único parcial (`WHERE status = 'ACTIVE'`) exigiria SQL manual na migration, e o app tem um único usuário.
- **`finalRating` como texto curto** (ex.: "Atende plenamente"), até a pergunta 4 ser respondida.

### E2E

`e2e/categories.spec.ts`:

1. A lista mostra as categorias padrão (o helper roda o mesmo seed depois de limpar o banco).
2. Criar categoria; nome repetido mostra o erro no campo.
3. Arquivar tira a categoria do select de uma nova ação; categoria em uso não oferece excluir.

`e2e/pdi.spec.ts`:

4. `/pdi` vazio mostra a mensagem e o link "Criar ciclo".
5. Criar ciclo ativo, área, ação e check-in; o detalhe mostra tudo e o progresso "0 de 1 ação concluída".
6. Concluir a ação pela edição atualiza o progresso do ciclo e do objetivo vinculado.
7. Ativar um segundo ciclo mostra o erro no campo status.
8. Encerrar o ciclo esconde os botões de edição e mostra o aviso; Reabrir devolve a edição.
9. Datas inválidas no ciclo mostram o erro no campo de fim.
10. Categorias, `/pdi`, detalhe do ciclo e formulários passam no axe.

## Decisões

1. Os campos do PDI conferem com o formulário da empresa (validado pelo dono do projeto em 16/11/2026).
2. Só um ciclo ativo por vez, regra no service.
3. Ciclo encerrado pode ser reaberto (volta para ativo); é a única operação permitida nele.
4. Avaliação final é texto livre curto (até 60 caracteres).
5. O progresso do objetivo soma etapas de trilha e ações de PDI (sem as canceladas), com detalhamento por tipo.
